# Dispute Evidence Off-Chain Storage & SHA-256 Attestation

In Cypher GridPay's arbitration and escrow architecture, smart contracts (`core/contracts/escrow` and `core/contracts/refund`) store cryptographic hashes and Content Identifiers (CIDs) on-chain rather than raw artifacts to minimize ledger storage fees and preserve confidentiality.

This document outlines the off-chain encrypted evidence storage architecture, attestation pipeline, and cryptographic access control policies.

---

## 1. On-Chain Hash Binding

- **Escrow Contracts** (`bulk_evidence_test.rs`): Dispute evidence is committed via 32-byte SHA-256 hashes or IPFS CIDs stored in contract storage under the dispute record.
- **Refund Contracts** (`RefundEvidence`): Holds customer/merchant attestation hashes for damaged goods, delivery failures, or metering discrepancies.

The off-chain storage service guarantees that:
1. The raw artifact's SHA-256 digest matches the on-chain hash byte-for-byte.
2. Artifacts are client-side encrypted before transmission.
3. Access is strictly scoped to the buyer, merchant, selected arbitrators, and emergency admin.

---

## 2. Envelope Encryption & Key Derivation

```
Client                                      Evidence Storage API                 IPFS / Encrypted S3
  │                                                   │                                    │
  │─── 1. Generate AES-256-GCM DEK ───────────────────┼────────────────────────────────────│
  │─── 2. Encrypt artifact locally ───────────────────┼────────────────────────────────────│
  │─── 3. Wrap DEK with Arbitrator Public Keys ───────┼────────────────────────────────────│
  │─── 4. POST /v1/disputes/:id/evidence ────────────►│                                    │
  │       (Payload: SHA-256, Wrapped Keys, Metadata)  │─── 5. Upload ciphertext ──────────►│
  │                                                   │◄── 6. Storage CID / Key returned ──│
  │◄── 7. Receipt with Attestation Hash ──────────────│                                    │
```

- **Data Encryption Key (DEK)**: Ephemeral AES-256-GCM symmetric key generated by the uploader.
- **Key Encapsulation**: The DEK is encrypted with the public keys (X25519) of all authorized parties:
  - Buyer wallet
  - Merchant wallet
  - Assigned dispute arbitrators (`select_arbitration_panel`)
- Only designated dispute participants can unwrap the DEK and decrypt the evidence file.

---

## 3. Storage Layer & Redundancy

Evidence payloads are stored in content-addressed storage across redundant providers:
- **IPFS Pinning**: Primary pinning across Pinata and local IPFS clusters.
- **Encrypted S3 Archive**: Encrypted backup bucket with object lock enabled (compliance retention).
- **Integrity Attestation**: The API computes `sha256(raw_bytes)` and generates an EIP-712/Stellar signed attestation proof for onchain submission.
